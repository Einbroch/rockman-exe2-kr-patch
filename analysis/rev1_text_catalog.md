# Rev 1 메시지 후보 카탈로그 검증 — `ss1` 상태 기준

## 기준선과 증거

- ROM: `Battle Network Rockman EXE 2 (Japan) (Rev 1)`
  - SHA-256: `1afe35e1d00099d62cbddad43c2be3f0f3c3f0f333e8df54456076cb2df6a6b8`
- 상태: `Battle Network Rockman EXE 2 (Japan) (Rev 1).ss1`
  - SHA-256: `819619baf8bef2360c6e2c55fa9adc6fc669932478cb6f20bc2b1907113f6914`
  - 240×160 PNG와 mGBA `gbAs` 상태 데이터(압축 해제 397,312 bytes)를 포함한다.
- 보조 자료: PC 패치 `exe2j.dat`의 `message_jap.map` 및 `message_jap.mpak`

## 카탈로그 판정

| 구분 | 수 | 판정 |
| --- | ---: | --- |
| PC 메시지 맵 레코드 | 427 | 모든 ROM/패키지 범위가 유효한 구조 후보 |
| 스크립트형 블록 | 242 | 선행 16비트 오프셋 테이블과 `ED`/`F1` 계열 제어 바이트가 함께 관측됨 |
| 구조 미확정 블록 | 185 | 텍스트가 아닌 테이블·폰트·기타 데이터가 섞여 있을 수 있어 보류 |
| 스크립트형 내부 항목 | 10,360 | 오프셋 테이블로 열거한 후보 단위; 아직 논리적 문장 수는 아님 |
| 런타임 포인터 관측 블록 | 1 | 아래 현재 대사 블록 |

427개는 PC 패치가 다룬 메시지 관련 데이터의 **구조 분모**다. 이 숫자를 곧바로
“427개 대사” 또는 “전량 추출 완료”로 해석하지 않는다. 예를 들어 맵 첫 블록은
문자/테이블성 데이터이며, 185개 미확정 블록은 제외하지 않고 계속 보존한다.

## 현재 화면과 연결된 항목

제공된 `ss1` 상태의 `gbAs` 데이터에서 다음 ROM 포인터가 한 번 관측됐다.

| 항목 | 값 |
| --- | --- |
| 블록 ID | `pc-jap-map-0023` |
| 내부 항목 ID | `pc-jap-map-0023/entry-00` |
| GBA ROM 주소 | `0x0877A2AE` |
| 파일 오프셋 | `0x0077A2AE` |
| 후보 길이 | 59 bytes |
| 원본 SHA-256 | `e6d121a664d2014393c1787af7e9fa8716bf285754dc97a9af1b3a396f2f2138` |

상위 블록은 11개 16비트 오프셋으로 시작하며, 이 항목은 첫 오프셋이 가리킨다.
상태 화면에는 실제 대사창이 표시되고, 이 내부 항목의 시작 포인터만이 427개 블록
및 10,360개 내부 후보 가운데 상태 데이터에서 관측됐다. 따라서 이 항목은
**현재 대사 렌더 경로의 런타임 관측 표본**으로 승격한다.

다만 `ED`, `F1`, `F9`, `FA` 계열 바이트의 인자 폭·의미, 문자 코드→글리프 매핑,
각 내부 항목의 정확한 종료자는 아직 소비 루틴에서 검증하지 않았다. 이 카탈로그는
원본 바이트·좌표·공유 시작점 해시를 보존하지만 원문을 추측해 디코드하거나
번역용 문장으로 확정하지 않는다.
