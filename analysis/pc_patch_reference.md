# PC판 패치 `exe2j.dat` 참고성 판정

## 결론

**참고 자료로 사용 가능하다.** 단, 이 파일의 PC용 바이너리·폰트·UI 자산을 GBA
패치에 그대로 옮기지 않는다. 확인된 가치가 있는 부분은 메시지 맵의 **대사 블록
후보 위치**와 중국어 번역의 **문맥 참고**다.

## 컨테이너와 리비전

- `exe2j.dat`는 암호화되지 않은 ZIP 컨테이너다(122개 멤버, 압축 해제 기준
  694,661,860 bytes).
- 내부 `exe2j/rom.srl`은 GBA 헤더상 `ROCKMAN_EXE2`, `AE2J`, 버전 `0`이다.
- 현재 한글화 기준 ROM은 같은 제목·코드의 버전 `1`이다. 전체 SHA-256이 다르므로
  PC 패치의 주소나 원본 기대 바이트를 Rev 1에 직접 적용해서는 안 된다.

## 메시지 맵에서 확인된 구조

`message_chs.map`, `message_cht.map`, `message_eng.map`, `message_jap.map`은 각각
3개 32비트 헤더 뒤에 3개 32비트 값의 레코드가 이어지는 형태다.

| 맵 | 선언 레코드 수 | 패키지 경계 안의 레코드 |
| --- | ---: | ---: |
| 일본어 / 간체 중국어 / 번체 중국어 | 427 | 427 |
| 영어 | 428 | 428 |

- 일본어와 간체 중국어는 같은 순서의 레코드 주소 목록을 가진다.
- 각 레코드의 두 번째·세 번째 값은 해당 `.mpak` 파일의 유효한 `offset + length`
  범위에 들어간다. 첫 번째 값은 `0x087291D0`–`0x087F2070` 부근의 GBA ROM 주소와
  대응하는 강한 후보다.
- 마지막 레코드의 주소는 정확히 끝 경계 `0x087F2070`이므로, 이 주소를 일반 대사
  시작점으로 단정하지 않고 맵 포맷을 추가 검증할 때까지 경계 레코드로 보류한다.

특히 맵 헤더가 가리키는 ROM 범위 `0x007291D0`–`0x007F2070`(끝 제외, 822,944 bytes)는
내부 Rev 0 ROM과 현재 Rev 1 ROM에서 SHA-256까지 바이트 동일하다. 따라서 이 범위에
한정하면 맵의 블록 위치는 Rev 1의 **텍스트 모집단 후보를 찾는 데** 사용할 수 있다.

## 사용 가능 / 금지 범위

사용 가능:

- 일본어와 간체 중국어 `.mpak`의 같은 레코드 순서를 이용한 대사 문맥 대조
- 427개 블록을 GBA 텍스트 추출 조사 우선순위로 삼기
- 번역 용어·이름·UI 명칭의 사람 검토용 참고

사용 금지 또는 보류:

- PC `.pak` 글꼴·UI·로고를 GBA에 복사하거나 GBA 폰트로 간주하는 일
- Rev 0 기준 주소·바이트를 Rev 1에 검증 없이 쓰는 일
- 중국어 번역을 자동으로 한국어 번역문으로 변환하거나 이식하는 일
- 패치 내부의 `rom.srl`/`rom_e.srl`이나 기타 게임 자산을 추출·커밋·배포하는 일

다음 단계에서는 맵 레코드별로 현재 ROM의 실제 문자열 경계·제어 코드·소비 루틴을
검증한 뒤, 검증된 항목만 GBA 추출 카탈로그에 승격한다.
