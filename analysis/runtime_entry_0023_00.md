# 런타임 표본 `pc-jap-map-0023/entry-00` 제어 경계

이 기록은 현재 `ss1` 대사 화면에서 관측된 항목만 다룬다. 다른 스크립트 블록에
일반화하지 않는다.

## 확정된 구조

| 항목 | 값 |
| --- | --- |
| Rev 1 ROM 주소 | `0x0877A2AE` |
| 파일 범위 | `0x0077A2AE`–`0x0077A2E9` (끝 제외) |
| 원본 길이 | 59 bytes |
| 상위 블록 내부 인덱스 | 11개 16비트 오프셋 중 첫 항목 |
| 런타임 상태 관측 | 블록 시작과 이 항목 시작 ROM 포인터가 연속된 상태 필드에서 각각 1회 관측 |

항목의 끝은 널 종료자가 아니라 상위 오프셋 테이블의 다음 시작점으로 정해진다.
따라서 재삽입 때 `00`을 종료자로 가정하거나, 고정 59바이트 슬롯으로 가정하면 안 된다.

## 언어 교차 증거

같은 PC 패치의 일본어·간체/번체 중국어·영어 패키지는 모두 이 항목을 가진다.
항목 길이는 각각 81, 65, 75, 101바이트로 다르지만, GBA 원본과 네 패키지의 시작
12바이트는 완전히 같다.

```text
ED 00 12  ED 02 01  FA 18  F9 00  F1 00
```

12바이트 뒤부터는 언어별 데이터가 달라진다. 이로써 위 공통 접두부는 문자 본문이
아닌 언어 독립 제어 시퀀스라는 강한 증거가 된다. 현재 보존 규칙은 다음과 같다.

- 공통 12바이트: `preserve` 후보
- 그 뒤 바이트: 문자 데이터와 추가 제어가 섞였을 수 있는 미해독 영역 (`forbidden`)
- 항목 경계: 상위 16비트 오프셋 테이블로 보존

`ED`가 2바이트 인자를 갖고 `FA`·`F9`·`F1`이 각각 1바이트 인자를 갖는다는 분할은
반복 패턴에 근거한 **가설**이다. 현재 증거만으로 의미·인자 폭을 확정하지 않으며,
렌더러 소비 루틴에서 확인하기 전에는 자동 인코더에 넣지 않는다.

기계 판독 근거는 `runtime_entry_0023_00.json`에 있다.
