록맨 에그제 2 한글패치 V0.9 - MENU362FIT 진단 빌드
===================================================

이 패키지는 정식 배포판이 아닙니다.


지금까지의 결과
---------------

  00/352 + 00/362 포인터 되돌림  ->  메뉴 정상
  00/352 만 되돌림               ->  메뉴 멈춤
  00/362 만 되돌림               ->  메뉴 정상   (원인 확정)
  00/362 를 빈 공간으로 이동      ->  메뉴 멈춤

원인은 아카이브 00/362 이고, 주소도 "뒤에 오는 것"도 아닙니다.
남은 것은 내용입니다.


00/362 가 어떤 아카이브인가
---------------------------

엔트리 192개가 전부 짧은 라벨입니다. 게임이 상태에 따라 번호로
하나를 골라 읽습니다.

  원본  : 가장 긴 엔트리 15바이트,  전체 1,660바이트
  한글판: 가장 긴 엔트리 43바이트,  전체 4,052바이트

원본이 최대 15바이트인 칸에 한글이 최대 43바이트로 들어가 있습니다.
엔진이 이 라벨을 고정 크기 버퍼로 복사한다면 넘칩니다. 고르는 엔트리가
게임 상태에 따라 달라지므로, 짧은 엔트리가 걸리면 멀쩡하고 긴 엔트리가
걸리면 멈추는 것도 설명됩니다.

크기 자체는 원인이 아닐 가능성이 큽니다. 00/362 의 2.16배 증가는
아카이브 381개 중 69위로 평범하고, 2배 넘게 커진 아카이브가 119개
있는데 그것들은 문제를 일으키지 않았습니다.


무엇이 다른가
-------------

00/362 를 다시 만들되, **원본보다 길어진 엔트리만** 일본어 원문
바이트로 되돌렸습니다. 원본 길이 안에 들어가는 한글 엔트리는 그대로
한글로 남습니다. 즉 모든 엔트리가 원본 길이 이하가 됩니다.

다시 만든 아카이브는 0x910000(패치가 건드리지 않은 0xFF 빈 공간)에
두고 포인터를 그쪽으로 돌렸습니다. 빌드할 때 그 자리가 정말 전부
0xFF 인지, 그리고 다시 만든 표가 스스로의 검사를 통과하는지 확인합니다.


결과 해석
---------

- 메뉴가 열린다
  → 엔트리 하나하나의 바이트 길이가 원인으로 확정됩니다.
    정식 수정은 00/362 의 한글 라벨을 원본 칸 크기에 맞게 줄이는
    것이고, 같은 조건의 다른 아카이브도 전수로 세어야 합니다.

- 여전히 멈춘다
  → 길이가 아니라 내용 자체(문자 코드나 제어 코드)의 문제입니다.
    그때는 엔트리를 절반씩 나눠 범위를 좁히겠습니다.


화면에 보이는 것
----------------

되돌린 엔트리는 일본어로, 짧은 한글 엔트리는 한글로 섞여 보입니다.
진단용이라 정상입니다.
