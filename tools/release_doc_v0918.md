# EXE2 Rev 1 한국어 패치 V0.9.18 (시험용)

원본 일본판 Rev 1 ROM에 동봉된 BPS 패치를 적용하세요(`APPLY_PATCH.cmd` 또는
동봉된 flips). 이전 패치 ROM에는 덧씌우지 마세요.

## 카탈로그 밖 대사 아카이브 9개를 더 번역했습니다

V0.9.17에서 길을 튼 방식으로, 포인터 스캔이 찾은 나머지 대사 아카이브를
모두 넣었습니다.

| 원본 주소 | 내용 | 번역 엔트리 |
|---|---|---|
| `0x0731C78` `0x07327E8` `0x073337C` `0x0733F08` | 스타일 체인지 이벤트 (브라더·커스텀·거츠·실드 × 4속성) | 52 × 4 |
| `0x0734B2C` | 싱크로율 200% — 사이토 스타일 | 22 |
| `0x07924C0` | 맨션 엘리베이터 층 선택 | 114 |
| `0x0797578` | 흡혈·좀비·도둑 프로그램 함정 | 5 |
| `0x07976B0` | 맨션 호실 전자파 제어 프로그램 | 40 |
| `0x07E8598` | 게시판 새 글 알림 | 3 |

V0.9.17에서 남겨 두었던 `0x0731310`의 선택창("넷토, 여기선 도망치는 게
좋을까?")과 "HP 최대" 라벨도 들어갔습니다.

## 번역 방식을 바꿨습니다: 문자열 칸 단위 치환

기존 draft 문법(`/`, `//`, `[tag]`)으로는 선택지 줄 끝의 개행·공백,
효과음을 사이에 둔 같은 줄 문자열, 문자열 앞 공백을 표현할 수 없습니다.
그래서 선택창 엔트리는 원문 골격조차 왕복하지 않았습니다(층 선택은 114개
전부 실패).

미카탈로그 아카이브는 이제 원본 TPL의 따옴표 문자열 하나하나를 칸으로 보고
**그 자리에서만** 바꿉니다. 제어 코드는 한 바이트도 움직이지 않습니다.
배치를 만들 때 검사하는 것:

- 칸 수 일치, 빈 칸 없음
- 가나·한자가 남은 칸 없음
- 모든 문자가 표로 인코딩되거나 한글
- 빌드의 치환과 따로 짠 치환의 결과가 같음
- 모든 페이지가 원문이 그리는 창 안 (선택지 커서 칸과 동적 이름 폭 포함)

빌드는 여기에 더해 컴파일된 바이트에서 **모든 칸의 문자열을 순서대로 다시
찾습니다**.

기존 35건을 새 방식으로 옮긴 뒤 빌드한 ROM이 **V0.9.17과 바이트 단위로
같다**는 것을 먼저 확인하고 나서 새 번역을 넣었습니다.

## 후속 스크립트 7건 추가

- 스타일 아카이브 5개 뒤에 붙은 아빠의 "덮어쓸까?" 선택창
- `0x0731310` 끝의 우드 실드 Lv3 문구 (V0.9.17에서 형제 문구 중 이것만
  일본어였습니다)
- **튜토리얼 배틀의 마리 선생님 대사 "지금은 연습이니까 ADD 버튼을 골라
  보세요"** — 새 아카이브가 경계를 나눠 주면서, 27만 바이트 갭에 묻혀 있던
  00/352의 꼬리가 37바이트 스크립트로 드러났습니다.

## 남은 것

- 대형 갭에 묻힌 꼬리 대사 2줄: 엘리베이터 "…이미 정상" 문구
  (`0x07976B0` 뒤), "배낭에 칩이 10장도 없다" (00/356 뒤). 대사 바로 뒤에
  다른 데이터가 붙어 있어 지금 방식으로는 번역할 수 없습니다.
- 기존 번역의 표기 불일치: サイトスタイル이 설명문에서는 "사이트 스타일",
  메뉴에서는 "사이토 스타일"입니다. 이번 대사는 "사이토 스타일"로 썼습니다.
- 칩 이름 2번 뱅크·칩 설명 2~4번 실기 확인.
- 카탈로그 쪽 선택창 부류 (비표준 창 넘침 94건 기록).
- 전체 게임 완주 QA.

## 검증

엔트리 8,290개, 후속 스크립트 번역 211건, 표준 창 위반 0건. 새 아카이브
10개를 가리키던 참조 18곳이 모두 새 주소로 다시 쓰였고 옛 주소 참조는
남지 않았습니다.
