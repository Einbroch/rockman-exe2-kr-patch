현재 후보가 계승한 linewrap-fix에는 일반 대화의 공백·줄 배치 수정도 포함한다.

제어는 바꾸지 않고, 원문에서 빠진 줄바꿈 복원과 기존 공백 위치를 이용한 배치만
적용한다. TextPet의 LF heredoc이 선두 빈 행을 삼키는 문제는 CRLF로 보존했다.
자동 테스트에서 `00/366/5`의 최대 가로 진행이 26칸에서 16칸으로 줄었고,
3줄 표시 및 대화 종료를 확인했다. `00/12/2`와 PET 선택창 두 선택·B 취소도
음소거 렌더러 주입 테스트를 통과했다. 자연 맵 진입 및 전체 게임 QA는 미완료다.

`analysis/exe2_rev1_dialogue_wrap_bytes_qa.json`, 런타임 근거는
`analysis/exe2_rev1_dialogue_wrap_runtime_qa.json`에 있다. 특수 창·변수 삽입·미해결
제어는 별도 감사 대상으로 남겼으며, 일반 창에서도 54페이지는 3줄 용량 등으로
자동 적용하지 않았다. 이 수치는 모든 미해결 넘침의 확정 수량이 아니다.

```powershell
python tools/survey_rom.py --rom "<원본-ROM-경로>" --output analysis/survey.json
```

`analysis/survey.json`의 압축 스트림·포인터·ASCII 결과는 모두 **후보**다.
원본 문자열 자체는 보고서에 저장하지 않고, ASCII 후보는 오프셋·길이·해시만
기록한다.
텍스트 구조, 제어 코드, 글리프 경로는 실제 런타임 소비자 또는 독립 증거로
검증되기 전까지 확정 사양으로 취급하지 않는다.

## 다음 판정 순서

1. 실제 대사 창을 재현하고, 화면 문자열과 ROM/메모리 바이트를 대응시킨다.
2. 그 문자열을 읽는 루틴에서 문자 폭·종료 코드·포인터 표현을 확정한다.
3. 폰트 타일의 원천·적재·VRAM 전송 경로를 확인한다.
4. 대표 대사 한 단위에 한글 글리프·인코딩·재삽입을 적용해 화면까지 검증한다.
5. 그 결과를 재현 가능한 빌드와 차분 패치로 승격한다.

원본 게임의 저작권 자료는 커밋하거나 배포하지 않는다.
